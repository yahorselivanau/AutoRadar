# PRD: AI-поиск автозапчастей в Беларуси

## 1. Видение продукта

Создать мобильный AI-first сервис, который помогает человеку описать нужную автозапчасть обычным языком, уточняет критичные параметры, выполняет живой поиск по нескольким белорусским каталогам и показывает сравнимую выдачу:

- новый оригинал;
- новый аналог;
- оригинал б/у.

Сервис не продаёт товар и не оформляет заказ. Он показывает предложения и перенаправляет пользователя на сайт источника.

## 2. Цель MVP

Проверить гипотезу на первых 500 пользователях:

> Люди будут использовать единый разговорный интерфейс, если он экономит время на подборе и сравнении автозапчастей между несколькими сайтами.

### Метрики проверки

- пользователь дошёл до выдачи;
- пользователь открыл предложение;
- пользователь перешёл на сайт продавца;
- доля поисков, где найден хотя бы один результат;
- медианное время до первого результата;
- доля поисков, потребовавших ручного уточнения;
- пользовательская оценка полезности после поиска.

## 3. Не входит в MVP

- оформление заказа и оплата;
- комиссия или реклама;
- собственный склад;
- полный импорт каталогов поставщиков;
- гарантированный подбор уровня TecDoc;
- собственная база применяемости для всех автомобилей;
- автоматический обход CAPTCHA;
- обход авторизации, платного доступа или технических ограничений источников;
- сложная система кеширования;
- отдельный поисковый движок;
- полноценный голосовой ассистент в реальном времени.

## 4. Пользователи

Единый продукт для:

- обычного автовладельца;
- автомеханика;
- сотрудника СТО;
- сотрудника магазина автозапчастей.

В MVP не создавать разные роли и интерфейсы для этих сегментов.

## 5. Основные способы поиска

### 5.1. Разговорный поиск

Пример:

> Нужен передний левый стеклоподъёмник на Peugeot 308 2008 года, три двери.

AI извлекает известные параметры, показывает их пользователю и задаёт только необходимые уточнения.

### 5.2. Поиск по OEM/артикулу

Пользователь вводит номер детали. Приложение:

1. сохраняет оригинальное значение;
2. создаёт нормализованное значение без пробелов, дефисов и служебных символов;
3. передаёт адаптеру оба значения;
4. применяет специфичное для источника форматирование;
5. не подменяет артикул похожим номером без подтверждения источника.

### 5.3. Поиск по VIN

Пользователь вводит VIN. Приложение:

1. нормализует регистр и пробелы;
2. проверяет базовый формат;
3. пытается определить автомобиль через `VehicleResolver`;
4. показывает найденные данные для подтверждения;
5. сохраняет VIN и подтверждённые параметры в гараж;
6. передаёт VIN только тем источникам, чей адаптер поддерживает такой поиск.

Автоматическое определение автомобиля является best-effort. Пользователь обязан подтвердить марку, модель и модификацию.

### 5.4. Ручной подбор автомобиля

Пользователь может выбрать:

- марку;
- модель;
- поколение;
- год;
- кузов;
- двигатель;
- коробку передач;
- дополнительные параметры, если они нужны конкретной детали.

Форма и AI-чат должны создавать один и тот же объект `VehicleContext`.

## 6. Гараж

Пользователь может сохранить несколько автомобилей.

Для каждого автомобиля:

- название для отображения;
- VIN;
- марка;
- модель;
- поколение;
- год;
- кузов;
- двигатель;
- коробка;
- дополнительные заметки;
- признак активного автомобиля.

В чате всегда виден активный автомобиль. Его можно сменить или отредактировать без выхода из диалога.

Гость получает полноценный value-first доступ: до пяти фактических AI-запросов
и пяти реальных запусков источников за скользящие 24 часа. Пустой «Новый
поиск» не сохраняется и не расходует лимит; каждая отправленная реплика,
включая продолжение старого диалога, расходует один AI-запрос. После лимита
история и результаты остаются доступны; вход нужен для новых запросов,
облачной синхронизации и переноса данных между устройствами.

## 7. AI-поведение

### 7.1. Роль модели

Модель:

- понимает естественный язык;
- извлекает параметры в структурированный JSON;
- определяет, каких данных не хватает;
- формирует короткие уточняющие вопросы;
- вызывает разрешённые инструменты;
- объясняет результат простым языком.

### 7.2. Запреты

Модель не должна:

- придумывать OEM-номера;
- придумывать совместимость;
- считать название детали достаточным доказательством совместимости;
- менять VIN;
- скрывать неопределённость;
- использовать общий веб-поиск как доказательство применяемости детали;
- выбирать товар вместо пользователя без объяснения критериев.

### 7.3. Инструменты AI

Минимальный набор:

- `get_active_vehicle`
- `list_user_vehicles`
- `save_vehicle`
- `update_vehicle`
- `resolve_vin`
- `parse_part_request`
- `start_parts_search`
- `get_search_status`
- `get_search_results`

Все входы инструментов валидируются Zod-схемами.

### 7.4. Модель

Использовать Vercel AI SDK и провайдер-абстракцию.

Модель задаётся переменной окружения. На текущем этапе разрешена только
`openai/gpt-5.4-nano` через Vercel AI Gateway. Модельные fallback и другие
провайдеры намеренно не подключаются до отдельной продуктовой задачи.

AI применяется для извлечения намерения и диалога. Поиск и сортировка предложений выполняются детерминированным кодом.

## 8. Пользовательский путь

### 8.1. Первый вход

1. Пользователь видит чат и короткие примеры запросов.
2. Может начать без регистрации.
3. Может выбрать режим:
   - описать деталь;
   - ввести номер;
   - ввести VIN;
   - выбрать автомобиль вручную.

### 8.2. Уточнение

AI выводит извлечённые параметры в редактируемом блоке:

- автомобиль;
- деталь;
- сторона;
- положение;
- состояние;
- OEM, если пользователь его предоставил.

Недостающие критичные параметры предлагаются кнопками прямо в чате.

### 8.3. Поиск

После подтверждения:

1. создаётся `search_job`;
2. пользователь видит прогресс по источникам;
3. первые результаты показываются сразу после появления;
4. общий поиск завершается по таймауту, даже если часть источников не ответила.

Целевые показатели:

- первый результат: до 10 секунд в нормальном сценарии;
- завершение основной выдачи: до 25 секунд;
- отказ одного источника не ломает общий поиск.

### 8.4. Результаты

В сообщении чата показывается компактное резюме:

- сколько найдено новых оригиналов;
- сколько новых аналогов;
- сколько б/у;
- диапазон цен;
- кнопка открытия полной выдачи.

Полная выдача:

- мобильный телефон: отдельный полноэкранный слой;
- desktop: большой dialog/drawer;
- закрытие возвращает пользователя в ту же позицию чата.

Группы:

1. Новый оригинал.
2. Новый аналог.
3. Оригинал б/у.
4. Неклассифицированные предложения — только если классификация сомнительна.

Карточка предложения:

- название;
- бренд;
- артикул/OEM;
- состояние;
- цена BYN;
- наличие или срок;
- город/доставка;
- продавец или источник;
- время получения данных;
- предупреждение о проверке совместимости;
- кнопка перехода.

## 9. Нормализация

### 9.1. Номер детали

Хранить:

- `raw_part_number`;
- `normalized_part_number`;
- `brand`, если известен;
- `source_part_number`.

Базовая нормализация:

- uppercase;
- удалить пробелы;
- удалить дефисы, точки и слеши для ключа сопоставления;
- не удалять символы из исходного значения.

### 9.2. Названия

Словарь синонимов создаётся постепенно из реальных поисков:

- стеклоподъёмник / механизм стекла / window regulator;
- левый / LH;
- правый / RH;
- передний / front;
- задний / rear.

AI может предложить каноническое название, но запись должна проходить валидацию доменным кодом.

### 9.3. Классификация предложения

`condition`:

- `new`
- `used`
- `unknown`

`part_kind`:

- `original`
- `analog`
- `unknown`

Если источник не даёт достаточных данных, использовать `unknown`, а не угадывать.

## 10. Источники

Приоритетные для первого цикла:

- ARMTEK — новые детали;
- AV-parts — новые детали/агрегированная выдача;
- Remzona — новые детали;
- Motorland — б/у детали.

Релизный минимум: не менее трёх стабильно работающих адаптеров новых деталей.
Bamper отложен и не блокирует MVP.

Архитектура поддерживает до десяти источников. Дополнительные кандидаты перечислены в `SOURCE_ADAPTERS.md`.

## 11. Доступность и мобильный UX

- mobile-first;
- все основные действия доступны одной рукой;
- минимальный размер интерактивной зоны — 44×44 px;
- ввод не перекрывается клавиатурой;
- результаты не сбрасывают состояние чата;
- состояние поиска восстанавливается после обновления страницы;
- базовый интерфейс работает без установки приложения;
- PWA — допустимое улучшение после основной версии.

## 12. Безопасность и приватность

- VIN считается чувствительным пользовательским идентификатором;
- не писать полный VIN в клиентские логи, аналитику и Sentry;
- в диагностике маскировать VIN;
- пользователь может удалить автомобиль и аккаунт;
- сервис не передаёт VIN AI-модели без технической необходимости;
- service-role ключ Supabase никогда не попадает в браузер;
- адаптеры не обходят CAPTCHA, авторизацию, paywall и явно запрещённый доступ;
- автоматический доступ прекращается, если публичный поиск нельзя
  воспроизвести без обхода защиты;
- TLS verification не отключается.

## 13. Ограничения бесплатного теста

Цель — до 500 первых пользователей.

Обязательные защитные меры:

- серверный rate limit;
- максимальное число источников на один поиск — 10;
- общий таймаут поиска;
- отмена повторного запуска по двойному нажатию;
- лимит параллельных заданий;
- feature flags для каждого источника;
- возможность мгновенно отключить дорогой или нестабильный адаптер.

Регистрация не показывается до получения реальной ценности. Гостю доступны
полноценные диалоги и несколько реальных поисков. Мягкое предупреждение
появляется до исчерпания лимита; после него блокируются новые AI-запросы и
новые запуски источников, но не открытие сохранённых диалогов.
Сохранённые результаты остаются читаемыми, а гостевые данные переносятся в
аккаунт после входа или регистрации по email и паролю. В приватном MVP
подтверждение email отключено, поэтому новая сессия создаётся сразу.

## 14. Критерии готовности MVP

MVP считается готовым, если:

- гость может выполнить поиск без аккаунта;
- AI корректно собирает структурированный запрос;
- ручная форма создаёт тот же формат запроса;
- VIN можно сохранить в гараж и подтвердить распознанный автомобиль;
- OEM-поиск работает минимум на трёх источниках;
- Remzona выдаёт реальные карточки новых запчастей;
- результаты источников появляются независимо;
- ошибка источника не ломает выдачу;
- на мобильном можно открыть результаты, перейти к продавцу и вернуться в чат;
- все внешние предложения содержат ссылку на исходную карточку;
- есть предупреждение о необходимости проверки совместимости;
- адаптеры покрыты fixture-тестами.
